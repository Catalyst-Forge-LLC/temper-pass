A called pass. Only run it when you have asked for it.

**Status:** Locked. Same-session validation, including a run that scored three hosts of the same database as if they were architectures.

A decision that cannot name its criteria will back-fit them after the favorite wins. This pass makes the criteria and the weights visible first.

**Use when** you ask for a tradeoff matrix, a scored comparison, or help choosing among real alternatives. **Do not use** unprompted, or when there is only one serious option.

Skill file: [`passes/tradeoff-matrix/SKILL.md`](https://github.com/Catalyst-Forge-LLC/temper-pass/blob/main/passes/tradeoff-matrix/SKILL.md)

## Protocol

1. Require at least three *meaningfully* different options. Vendor, region, or color for the same architecture is one option with a footnote.
2. Derive criteria from the stated success condition, not from the options. Maximum five.
3. Weight before scoring. If you catch yourself scoring first, discard the scores and start over.
4. Score, then one line: "This decision turns on X."
5. Stop. Do not implement the winner unless asked.

If the options are not actually different, or there is no success condition, do not invent a matrix to fill the format.

A first run scored Railway vs Fly vs Render Postgres. They collapse. Transcripts: [`examples/tradeoff-matrix-transcripts.md`](https://github.com/Catalyst-Forge-LLC/temper-pass/blob/main/examples/tradeoff-matrix-transcripts.md).
